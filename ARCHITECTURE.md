# Архитектура векторного редактора для лазерной резки

**Рабочее имя:** `lasercut-studio` (подставим ваше)
**Цель:** браузерный редактор «мм 1:1» для лазерной резки и гравировки: открыть DXF/SVG → поправить → проверить пригодность к резке → сохранить DXF для станка (LightBurn / RDWorks / CorelLaser).
**Документ-этап:** архитектура и план. Кода пока нет — по нему начинаем следующий шаг.

---

## 0. TL;DR — стек и главные решения

| Решение | Выбор | Почему |
|---|---|---|
| Язык | **TypeScript, `strict`** | Геометрия прощает ошибки до первого «сварить» двух контуров. |
| Сборка | **Vite** (библиотечный режим не нужен) | мгновенный dev-server, `?raw` для шрифтов, WASM из коробки |
| UI-фреймворк | **нет** (шаблоны + мелкий рендер-цикл) | 95 % экрана — канвас; React даёт лишний вес и мешает 60 fps. Панели — обычный DOM |
| Рендер | **Canvas 2D** с двумя слоями (сцена + оверлей), `Path2D`-кэш | 5–10 тыс. путей держит без боли; SVG-DOM умрёт на 20 тыс. узлов |
| Булевы операции и offset | **clipper2-wasm** (Clipper2, WASM) | самая быстрая и проверенная; в целых координатах через масштаб 1e4 |
| Спатиальный индекс | **rbush** (~3 КБ) | hit-test и рамка выделения за O(log n) |
| Шрифт → кривые | **opentype.js** (MVP), при нужде — harfbuzzjs | кириллица в MVP достаточно; сложный шейпинг позже |
| DXF-импорт | **свой парсер** (групп-коды простые) + фикстуры | чужие парсеры теряют блоки, сплайны и bulge-семантику |
| DXF-экспорт | **свой райтер**, R2000 по умолчанию, R12 по флагу | полный контроль над слоями и замкнутостью контуров |
| Хранение | localStorage (автосейв) + IndexedDB (крупные) + `.lcx` (JSON) | офлайн-работа без бэкенда |
| Тесты | **vitest** (геометрия, round-trip DXF) + визуальная регрессия | DXF ломается тихо, ловится только фикстурами |

**Без бэкенда на первом этапе.** Всё клиентское. Сервер понадобится только для DWG/CDR (LibreDWG/libcdr) и для заказов — отдельным сервисом, редактор от него не зависит.

## 1. Границы продукта

### MVP (v1.0)
- Документ: лист в мм, сетка, привязки, направляющие, несколько листов.
- Рисование: линия, прямоугольник (скругление), эллипс/сектор/дуга, кривая Безье, текст (2–3 шрифта) → в кривые.
- Правка: выделение (клик/рамка/`Shift`), перемещение, точные X/Y/W/H, поворот, узлы (добавить/удалить/в кривую/разрыв/замыкание), группы.
- Операции: сварить / вычесть / пересечь / исключить, контур наружу/внутрь (offset), копии по ряду и по кругу.
- Импорт: DXF (R12/R2000+), SVG. Экспорт: DXF (слои «рез»/«гравировка»), SVG, PNG.
- Проверка перед резкой: незамкнутые контуры, дубли линий, объекты за пределами листа, текст не в кривых.
- Undo/redo, автосейв, горячие клавиши.

### Не в MVP (v2+)
DWG/CDR (сервер), векторизация растровых картинок, генератор параметрических моделей, размеры как объекты-ассоциативы, вложенные блоки с редактированием, сплайны с сохранением контрольных точек (в MVP — через bulge/кривые Безье), DXF-атрибуты, штриховка HATCH, DIMENSION как объект (в MVP — экспорт как линии), многопользовательская работа.

### Явно не делаем никогда
Полноценный CAD (размеры по ГОСТ, ассоциативные чертежи), 3D, рендер физики резки.

## 2. Слоистость (кто кого знает)

```
┌───────────────────────────────────────────────────────────┐
│ UI (панели, диалоги, меню)          DOM, без знания геометрии│
├───────────────────────────────────────────────────────────┤
│ Tools (state machine ввода)         знает Store + Geom      │
├──────────────────────────┬────────────────────────────────┤
│ State (Store, History,   │ Render (View, Scene, Overlay)   │
│ Selection, Commands)     │                                 │
├──────────────────────────┴────────────────────────────────┤
│ Core: Doc · Geom · Path · Boolean · DXF · SVG · Validate    │
│        ← чистые функции, без DOM, тестируются в node        │
└───────────────────────────────────────────────────────────┘
```

Правило: **`core/` не импортирует ничего из `render/`, `ui/`, `tools/`**. Всё, что можно проверить тестом в node, живёт в `core/`.

Направление данных — однонаправленное: `Tool → dispatch(Command) → Store.apply(patch) → subscribe → render`. Рендер никогда не меняет модель.

## 4. Модель документа

Единая единица измерения документа — **миллиметр**, всегда. Никаких px в модели: px живут только во `View`.

```ts
// core/types.ts
export type Id = string;                     // nanoid(10)
export type Mm = number;                     // всегда миллиметры, 1e-4 точность

export interface Doc {
  schemaVersion: 1;
  units: 'mm';
  sheets: Sheet[];                           // лист = пространство резки
  activeSheetId: Id;
  layers: Layer[];                           // слои-операции, не «рисовальные»
  objects: Record<Id, Obj>;                  // плоский словарь, порядок = z-index в order
  order: Id[];                               // порядок отрисовки
  meta: { name: string; createdAt: string; app: 'lasercut-studio' };
}

export interface Sheet {
  id: Id;
  name: string;
  width: Mm; height: Mm;                     // 300×200 по умолчанию
  origin: 'bottom-left';                     // как в DXF, ось Y вверх
  showGrid: boolean; gridStep: Mm;           // 0.5 | 1 | 5 | 10
  snapGrid: boolean; snapObjects: boolean;
  guides: { id: Id; axis: 'x' | 'y'; at: Mm }[];
}

export type Op = 'cut' | 'engrave' | 'score';       // рез | гравировка | разметка

export interface Layer {
  id: Id;
  name: string;                              // «рез», «гравировка»
  op: Op;
  color: string;                             // ACI при экспорте в DXF
  visible: boolean; locked: boolean;
  order: number;                             // порядок реза
}

export interface ObjBase {
  id: Id;
  sheetId: Id;
  layerId: Id;
  name?: string;
  transform: Mat2x3;                          // локальная → лист
  style: { fill?: string | null; stroke: string; strokeWidth: Mm; opacity: number };
  locked?: boolean; hidden?: boolean;
  parentId?: Id | null;                       // группа
}

export type Obj =
  | (ObjBase & { kind: 'path';   path: SubPath[] })      // всё, что угодно, кроме текста
  | (ObjBase & { kind: 'text';   text: TextSpec })       // живёт до «в кривые»
  | (ObjBase & { kind: 'group';  children: Id[] })
  | (ObjBase & { kind: 'image';  href: string; pxPerMm: number });  // v2

/** Подпуть: сегменты либо прямые, либо кубические Безье. Дуги храним как дуги до экспорта. */
export interface SubPath {
  closed: boolean;
  segs: Seg[];                                // segs[i].b === segs[i+1].a (инвариант)
  start: Vec2;                                // = segs[0].a
}
export type Seg =
  | { t: 'l'; a: Vec2; b: Vec2 }                                  // линия
  | { t: 'c'; a: Vec2; c1: Vec2; c2: Vec2; b: Vec2 }              // кубическая Безье
  | { t: 'a'; a: Vec2; b: Vec2; center: Vec2; r: number; a0: number; sweep: number }; // дуга (рад)

export interface TextSpec {
  value: string;
  fontId: string;                             // 'montserrat' | 'ptsans' | 'custom:<url>'
  sizeMm: Mm;
  align: 'left' | 'center' | 'right';
  letterSpacingMm: Mm;
  lineHeight: number;
  /** если true — при любом изменении геометрии конвертируем в path (см. §7) */
  outline: boolean;
}

/** Аффинная матрица 2×3: [a c e; b d f] — как в Canvas/SVG */
export interface Mat2x3 { a: number; b: number; c: number; d: number; e: number; f: number }
```

### Инварианты (проверяются в dev-режиме `assertDoc`)
1. Все `Id` уникальны; `order`, `children`, `layerId`, `sheetId` ссылаются только на существующие объекты.
2. `segs` подпути непрерывны: конец предыдущего = начало следующего (допуск 1e-9). Нарушение — баг, а не «почти работает».
3. `closed: true` ⇒ последний сегмент кончается в `start`.
4. У `path` минимум один `SubPath` с минимум одним сегментом.
5. `transform` всегда разложима (без вырожденного масштаба 0).
6. Геометрия хранится в локальных координатах, `transform` — единственный источник позиции/поворота/масштаба. Это критично: перемещение 500 объектов = 500 изменений матрицы, а не 50 000 координат.

### Почему плоский словарь, а не дерево
- Undo-патчи адресуются по `id`, а не по пути `a.b.c[3]`.
- `rbush` индексирует объекты по `id` и обновляется точечно.
- Группы — это ссылки (`children`), а не вложенность: объект всегда лежит в листе, но может принадлежать группе.

## 5. Геометрическое ядро

### 5.1 Представление
Дуги храним **как дуги**, а не как Безье: при экспорте в DXF дуга должна стать `ARC` или bulge-вершиной, иначе станок получит лишние сегменты и другой G-код. Безье — только там, где пришло из SVG или нарисовано пользователем.

`arc.toCubics(arc, tolerance)` — для рендера и для булевых операций; `arcFromBulge(p, q, bulge)` / `bulgeFromArc()` — для DXF.

### 5.2 Публичный API (то, чем пользуются tools)

```ts
// geom/path.ts
build(sub: SubPath[], closed: boolean): SubPath[];
transform(p: SubPath[], m: Mat2x3): SubPath[];
reverse(sub: SubPath): SubPath;              // для вычитания дырок
bbox(p: SubPath[]): Box;                     // с учётом экстремумов Безье, не по контрольным точкам!
length(p: SubPath[]): Mm;
nearestPoint(p: SubPath[], at: Vec2, toleranceMm: Mm): { point: Vec2; t: number; sub: number } | null;
splitAt(p: SubPath[], sub: number, t: number): [SubPath, SubPath];
```

**Ловушка №1:** bbox по контрольным точкам Безье завышен — объект «выделяется» в пустоте. Реализуем точные границы через решение производной (`bezierExtrema`). Это то место, где самодельные редакторы выглядят неаккуратно.

### 5.3 Флаттенинг и булевы операции

```
Path (line/cubic/arc)
   ↓ flatten(tolerance = 0.01 мм по умолчанию)      ← геометрия режется по станку, 0.01 не видно
Polygon[] (float, мм)
   ↓ scale(1e4)                                      ← Clipper2 работает в целых
Clipper2 (Path64) → union | diff | intersect | xor
   ↓ unscale, simplify(0.005 мм)
SubPath[] из полилиний (замкнутые)
```

- Булева операция **всегда теряет Безье и дуги** — это нормально и ожидаемо, предупреждаем в UI один раз («после операции контуры станут полилиниями»).
- Точность: масштаб 1e4 → дискретность 0.1 мкм; координаты до 3000 мм = 3·10⁷, в int64 запас огромный.
- `clipper2-wasm` грузим **лениво** (`await initClipper()` при первом булевом/offset) — 1.2 МБ в стартовый бандл не тащим.
- FillType: `EvenOdd` по умолчанию (привычно по Corel), переключатель на `NonZero` для SVG.

### 5.4 Offset (контур наружу/внутрь)
`ClipperOffset` с `JoinType.Round` (по умолчанию), `Miter` с лимитом. Два режима, как у людей: **поправка на рез** (0.05–0.1 мм, тонкая) и **обводка** (2–3 мм, заметная). Оба — одна и та же функция с разными аргументами.

### 5.5 Привязки (snap)
Порядок приоритета: узел/конец → пересечение → центр → середина сегмента → направляющая → сетка. Кандидаты собираются из `rbush`-запроса в радиусе `12 px / scale` мм. Результат — `{ point, kind }`, тип подсвечивается разным цветом/иконкой.

### 5.6 Валидация

```ts
// core/validate.ts
export type Issue =
  | { code: 'open-contour'; objectId: Id; at: Vec2 }
  | { code: 'duplicate-line'; objectIds: [Id, Id] }
  | { code: 'text-not-outlined'; objectId: Id }
  | { code: 'outside-sheet'; objectId: Id; overflowMm: number }
  | { code: 'self-intersect'; objectId: Id; at: Vec2 }
  | { code: 'zero-length'; objectId: Id };
```
Проверки: `open-contour` (замкнутость всех подпутей, кроме engrave), `duplicate-line` (совпадение отрезков в пределах 0.01 мм), `zero-length`, `outside-sheet`, `self-intersect` (по Clipper2 `SelfIntersect` — только по требованию: дорого), `text-not-outlined`.

## 6. DXF: импорт и экспорт

### 6.1 Формат: что реально важно
DXF — это пары строк «групп-код / значение». Всё остальное — детали.

```
  0
LWPOLYLINE
  8
CUT
 90
4
 70
1
 10
0.0
 20
0.0
 42
0.4142        ← bulge: tan(угол/4), знак = направление
 10
50.0
 20
0.0
```

Собственный райтер даёт полный контроль и ~200 строк кода — принимаем это решение.

**Версии:**
- `AC1015` (R2000) — по умолчанию: `LWPOLYLINE` с bulge, `ELLIPSE`, `SPLINE`, точные дуги в одной сущности.
- `AC1009` (R12) — флаг «максимальная совместимость» для старых RDWorks/CorelLaser: там нет `LWPOLYLINE`, только `POLYLINE` + `VERTEX` + `SEQEND`, и нет `ELLIPSE`.

### 6.2 Таблица маппинга импорта

| DXF | → модель | Замечания |
|---|---|---|
| `LINE` | `SubPath` 1 линия, open | |
| `LWPOLYLINE` (+`42` bulge) | `SubPath`, сегменты `l`/`a` | closed по `70 & 1`; bulge → дуга |
| `POLYLINE`/`VERTEX`/`SEQEND` | как выше | R12-путь CorelDRAW, обязателен |
| `CIRCLE` | 2 дуги по 180° | не 4 и не 360 (станки любят разрыв на старте) |
| `ARC` | дуга, CCW от `50` к `51` | DXF-дуги всегда CCW |
| `ELLIPSE` | 2–4 кубические | параметр `42` = 1 ⇒ это круг |
| `SPLINE` | кубические через де Бура → `c`-сегменты | degree 3 — основное; остальное — флаттенинг |
| `TEXT`/`MTEXT` | `text` с сопоставлением шрифта | если шрифта нет — сразу «в кривые» приближенным контуром + предупреждение |
| `INSERT` (блок) | рекурсивный импорт с матрицей вставки | глубина ≤ 8, защита от циклов |
| `HATCH` | **не импортируем** (v2), пишем в отчёт | |
| `DIMENSION` | конвертируем в линии+текст (или в блок, если он есть в `BLOCKS`) | |
| `POINT`, `XLINE`, `RAY` | игнор, в отчёт | |

**HEADER:**
- `$INSUNITS` — 1=дюймы, 4=мм, 5=см, 6=м (0/отсутствует = «без единиц», спросить пользователя или трактовать как мм с предупреждением).
- `$EXTMIN/$EXTMAX` — для «зум под чертёж» и подгонки листа.
- `$MEASUREMENT` — 1 = метрика (запасной признак).

**TABLES → LAYER:** имя, ACI-цвет (`62`), флаг выключенного слоя (`62` отрицательный), locked (`70 & 4`). Слой «0» трактуем как обычный. Цвет `7` = «по слою/чёрный».

**BLOCKS:** разворачиваем на месте, сохраняя `INSERT`-матрицу. Так теряется возможность править блок как блок, зато «разгруппировать и порезать» работает сразу.

### 6.3 Маппинг экспорта

```
Layer(op='cut')      → слой DXF «CUT»,     ACI 1 (красный)   ← LightBurn: красный = рез
Layer(op='engrave')  → слой DXF «ENGRAVE», ACI 5 (синий)
Layer(op='score')    → слой DXF «SCORE»,   ACI 3 (зелёный)
```
- Каждый замкнутый контур — одна `LWPOLYLINE` (не набор `LINE`): это главное, что делает файл «дружелюбным» к LightBurn/RDWorks.
- Дуги по возможности остаются bulge-вершинами; Безье — флаттенинг с `0.01 мм` (или экспорт как `SPLINE`, флагом).
- `$INSUNITS = 4`, `$LUNITS = 2` (десятичные), `$LUPREC = 4`, `$EXTMIN/$EXTMAX` пересчитываем.
- Ничего лишнего: никаких размерных линий, заливок и `HATCH` — только геометрия реза.
- Тест: файл после экспорта открывается в LibreCAD / Inkscape / LightBurn без ошибок (в CI — только LibreCAD CLI-проверка синтаксиса).

### 6.4 Ловушки, которые надо помнить (в `docs/DXF-NOTES.md`)
1. **Bulge положителен при движении против часовой стрелки**; `bulge = tan(Δ/4)`, где `Δ` — угол дуги. Ошибка знака = зеркальные дуги.
2. Дуги DXF — **всегда CCW** от `50` к `51`; CW-дуга = LC-совместимая запись через bulge<0 в полилинии.
3. Порядок объектов в DXF — порядок реза у части станков. Экспортируем по `layer.order`, затем изнутри наружу (дырки раньше контура).
4. `LWPOLYLINE` координаты — только X/Y (`10`/`20`), никаких `30` (Z).
5. Текст в DXF — это `TEXT` со стилем, а не кривые: если станок не понимает шрифт, получите мусор. Поэтому по умолчанию экспортируем текст **в кривые**.
6. Кодировка: R2000+ — UTF-8 с `$DWGCODEPAGE=ANSI_1251` для старых читателей; R12 — только ASCII, имена слоёв латиницей (`CUT`, `ENGRAVE`).

## 7. SVG и текст

**Импорт SVG:** `DOMParser` (без библиотеки) → обход дерева → `d` через свой мини-парсер (M/L/H/V/C/S/Q/T/A/Z, относительные и абсолютные) → `transform` из атрибутов каскадом. `px/pt/mm/in` в мм по CSS-соотношениям (96 dpi). `stroke-width` не разворачиваем в контур автоматически — предупреждаем, что обводка не режется.

**Экспорт SVG:** те же подпути, `viewBox` в мм, `width="300mm"`, цвета по слоям, `stroke-width` только по `score`. Для LightBurn SVG — равнозначный путь, держим его первоклассным.

**Текст → кривые:** `opentype.js` `font.getPath(text, x, y, size)` → `Path` команды → `SubPath`. Кернинг из `kern`/`GPOS pair`, кириллица покрывается. Ограничение MVP: нет лигатур/арабского шейпинга; если понадобится — harfbuzzjs как отдельный модуль за тем же интерфейсом `TextShaper`.

```ts
export interface TextShaper {
  layout(text: string, spec: TextSpec, font: LoadedFont): { advances: number[]; kern: number[] };
}
export interface FontSource { load(fontId: string): Promise<LoadedFont> } // woff2/ttf, self-host
```
Шрифты **только свои** (`public/fonts/`), не Google Fonts: приватность, офлайн, скорость (см. уроки ниже).

## 8. Рендер

### 8.1 Модель отрисовки

```
View { scale, tx, ty }  ← экран↔мм:  mm → (mm.x*scale+tx, H - (mm.y*scale+ty))
```
Ось Y документа — **вверх** (как в DXF), поэтому во `View` есть инверсия; делаем её один раз и в одном месте, а не «по месту» в каждом инструменте.

Два `<canvas>` друг над другом:
1. **scene** — сетка, лист, объекты (перерисовывается при изменении модели/вида);
2. **overlay** — выделение, ручки, узлы, привязки, «резинка» (перерисовывается каждый кадр при перетаскивании, дешёвая).

`Path2D` кэшируется по `obj.id + hash(path)`: пересобираем только изменённые объекты. `ctx.setTransform(dpr*scale, 0, 0, -dpr*scale, ...)` — рисуем в мм напрямую.

Особенности Canvas для «толстых» линий: `lineWidth` в мм × scale, но при `scale < 0.3` принудительно ставим `max(lineWidth, 1/dpr)` px, иначе рез «исчезает» при отдалении. Это типовая жалоба к самодельным редакторам.

### 8.2 Производительность — бюджеты

| Сценарий | Бюджет | Как держим |
|---|---|---|
| Открытие файла 5 тыс. контуров | < 600 мс | парсер за один проход, `rbush` один раз |
| Панорама/зум | 60 fps | только `setTransform` + culling по bbox |
| Перетаскивание 200 объектов | 60 fps | overlay отдельно, сцена не перерисовывается |
| Булева операция 2 тыс. вершин | < 150 мс | flatten 0.01 мм + int64 |
| Автосейв 1 МБ документа | < 30 мс | debounce 800 мс, `JSON.stringify` в idle |

Culling: объекты вне `viewBox` не рисуем; при `scale < 0.15` контуры рисуем батчами в один `Path2D`.

## 9. Состояние, undo/redo, инструменты

### 9.1 Store

```ts
interface AppState {
  doc: Doc;
  selection: Id[];
  activeTool: ToolId;
  view: { scale: number; tx: number; ty: number };
  hover: { objectId?: Id; node?: NodeRef; snap?: SnapResult };
  ui: { rightPanel: 'props' | 'layers' | 'check'; dialog?: DialogId; issues: Issue[] };
}
type Listener = (s: AppState, change: Change) => void;
```

Без Immer/Zustand: ручной `store.set(patch)` + явные подписки (`doc`, `selection`, `view`, `ui`). Документ меняется **только** через команды.

### 9.2 Undo/Redo как патчи, а не снапшоты

```ts
type Patch =
  | { op: 'add'; after: Obj }
  | { op: 'remove'; before: Obj }
  | { op: 'update'; id: Id; before: Obj; after: Obj };   // храним объект целиком — проще и предсказуемо

interface Command { label: string; patches: Patch[] }
```
- Стек на 100 шагов, каждый шаг — компактный набор объектов (документ на 5 МБ в снапшотах съел бы память за 20 движений).
- Транзакции: `begin → много update → commit(label)` — перетаскивание = один шаг undo.
- Stack «грязных» листов: undo через несколько листов переключает лист автоматически.
- `history.clear()` обнуляется при открытии файла.

### 9.3 Инструменты — конечный автомат, не набор if

```ts
export interface Tool {
  id: ToolId;
  cursor: string;
  onActivate?(ctx: ToolCtx): void;
  onDeactivate?(ctx: ToolCtx): void;
  onPointerDown(e: PtrEvt, ctx: ToolCtx): void;
  onPointerMove(e: PtrEvt, ctx: ToolCtx): void;   // превью на overlay, не в модели
  onPointerUp(e: PtrEvt, ctx: ToolCtx): void;     // создаёт команду
  onKey(e: KeyEvt, ctx: ToolCtx): 'handled' | 'pass';
  onDoubleClick?(e: PtrEvt, ctx: ToolCtx): void;
  onCancel(ctx: ToolCtx): void;                    // Esc
}
```
`ToolCtx` = `{ store, view, toMm(evt), toScreen(pt), commit(cmd), preview(layerFn) }`. Инструменты **не** трогают DOM панелей, панели читают store.

Клавиши (по привычке из Corel/Illustrator): `V` выбор, `P` кривая/перо, `R` прямоугольник, `E` эллипс, `L` линия, `T` текст, `N`/`F10` узлы, `Space` панорама, `Ctrl+Q` в кривые, `Ctrl+U` разгруппировать, `Ctrl+G` группировать, `Ctrl+Z/Y`, `Ctrl+Shift+O` контур, `+/-` зум, `Ctrl+0` весь лист, стрелки 1 мм / `Shift` 10 мм / `Ctrl` 0.1 мм, `Alt` — отдельная ручка.

### 9.4 Координация слоёв и операций
- Цвет и слой — разные вещи: цвет = визуал, `layer.op` = технология. При отправке в DXF слой определяет ACI-цвет. Не даём создать объект без слоя.
- «Разгруппировать» после импорта DXF — обязательная кнопка первого шага: импорт всегда приходит одной группой (как в RobX 2D — это правильно).

## 10. Хранение

| Что | Где | Когда |
|---|---|---|
| Автосейв текущего документа | `localStorage`, ключ `lcs.doc.v1` | debounce 800 мс, при `visibilitychange` |
| Тот же документ, если > 4 МБ | IndexedDB (`docs` store) | по размеру |
| Последние 10 проектов | IndexedDB | список на старте |
| Файл проекта | `.lcx` = JSON (`schemaVersion`) | «Сохранить в файл» / «Открыть .lcx» |
| Настройки | `localStorage` | тема, последние шрифты |

Почему не «только localStorage»: 5 МБ лимита и потеря при чистке кэша — самый частый способ убить доверие пользователя. Поэтому: явная кнопка «экспорт проекта в файл» и предупреждение в UI, что автосейв локальный.

`schemaVersion` + `migrate.ts` с первого дня — иначе первая же смена модели документа сделает старые автосейвы мусором.

## 11. Тестирование

1. **Unit (vitest), `core/`:** bbox для Безье против эталона, split/join, arc↔bulge round-trip (`bulge→arc→bulge` = исходное значение ±1e-9), simplify, offset на «дырке в плате», валидатор на 6 подготовленных битых файлах.
2. **Golden DXF:** `tests/fixtures/dxf/*.dxf` → `parse → map` → сравнение с `tests/golden/*.json` (с допуском 1e-6). Сюда кладём реальные выгрузки: CorelDRAW R12, LightBurn, AutoCAD R2018, файл с блоками, файл в дюймах, файл без `$INSUNITS`.
3. **Round-trip:** `dxf → doc → dxf → doc` — второй проход идентичен первому (кроме неизбежного).
4. **Визуальная регрессия:** puppeteer + сравнение png канваса на 8 сценах (лист, зум 367 %, выделение, узлы, булева, offset, гравировка, ошибки валидации). Порог по пикселям, а не «0 — идеально».
5. **Фаззинг парсера:** случайные/усечённые DXF не должны ронять вкладку (обязательный `try/catch` + лимиты на глубину `INSERT`, число сущностей, размер файла).
6. **Ручной чек-лист «файл доехал до станка»:** LightBurn, RDWorks, CorelLaser — 3 реальных файла, каждый релиз.

7. **PWA** (manifest + service worker) — редактор клиентский, офлайн-режим почти бесплатен и это реальное преимущество.
8. **Аналитика событий** с первого релиза: `import`, `boolean`, `offset`, `export_dxf`, `validation_failed` — иначе не узнать, где отваливаются люди.

10. **A11y-минимум:** подписи иконочных кнопок, `tabindex` на канвасе, шрифт панелей 13 px, а не 11.

## 16. Плагин для Moodle: `mod_lasercutstudio`

Редактор встраивается в Moodle как **активный модуль курса** — не как отдельный сервис и не как
внешний ресурс. Причина: сдача, оценка, права и приватность должны жить в Moodle, иначе
преподаватель получает ещё один «чужой» интерфейс.

### 16.1 Как устроена интеграция

```
view.php ──iframe──▶ editor.php ──▶ editor/index.html (сборка редактора, 492 КБ)
   │                                     ▲
   │  <script id="lcx-parent-config">    │ <script id="lcx-moodle-config"> + bridge.js
   ▼                                     ▼
js/parent.js  ◀──postMessage('ready'|'submit')──  бриф-мост внутри iframe
   │
   ├─ input[name=project] = JSON макета
   └─ форма moodleform → submit.php → submission::save() ─┬─ lasercutstudio_submissions
                                                          └─ filearea 'submission' (itemid=userid)
```

Решения:

1. **postMessage, а не общий JS-контекст.** Редактор — самодостаточная сборка, которая ничего не
   знает про Moodle; мост (`editor/bridge.js`) добавляется в момент отдачи `editor.php` и общается
   с родительской страницей сообщениями. Так сборку можно менять, не трогая плагин, а плагин —
   не пересобирая редактор.
2. **Один активный `.lcx` на пользователя** (`itemid = userid`, уникальный индекс
   `lasercutstudio,userid`). Пересдача обновляет запись и заменяет файл в filearea, а не создаёт
   новую версию: студенту нужен «текущий макет», историю попыток ведёт журнал оценок.
3. **Файлы — только через `pluginfile`**, с проверкой контекста: студент получает свой макет,
   преподаватель (`:viewsubmissions`) — любой в рамках элемента курса.
4. **Лимит 4 МБ на `.lcx`** (`submission::MAX_PROJECT_BYTES`), до 5 вложений. Проверяется и в JS
   (до отправки формы), и на сервере.
5. **Оценка ставится и в таблицу сдачи, и в журнал** (`grade_item` + `grade_grades`): статус
   «Оценено» — для интерфейса, журнал — для отчётов Moodle.

### 16.2 Ловушки Moodle, на которые уже наступили

| Симптом | Причина | Решение |
|---|---|---|
| `course_module_viewed`/`graded` не появляются в отчётах | события не объявлены в `classes/event` | объявлены, `get_objectid_mapping` для модуля |
| Восстановление курса падает с `unknown_context_mapping` | в `define_structure()` забыт `prepare_activity_structure($paths)` — задача не знает старый `contextid`, файлы некуда мапить | вызывать в конце `define_structure()` |
| Moodle считает модуль «defective» при удалении курса | колбэки названы `mod_lasercutstudio_delete_instance` вместо `lasercutstudio_delete_instance` | ядро зовёт `{modname}_*`; префикс `mod_` — только у `mod_lasercutstudio_pluginfile` |
| Оценка не попадает в журнал | в `grade_update()` передан объект вместо массива по пользователям | `[$userid => $grade]` |
| `dml_missing_record_exception` при сохранении | `file_save_draft_area_files(0, …)` — нет контекста пользователя | пропускать пустой `draftitemid` |
| Форма сдачи «ничего не делает» | у `moodleform` action по умолчанию — текущая страница | передавать `new moodle_url('/mod/lasercutstudio/submit.php', …)` в конструктор |
| `Class "mod_lasercutstudio_mod_form" not found` при добавлении/редактировании элемента курса | после массового переименования колбэков (без префикса `mod_`) задело и класс формы настроек | класс должен называться ровно `mod_<modname>_mod_form` (ядро строит имя в `course/modedit.php:162`); колбэки — наоборот, без префикса. Проверяется в `npm run moodle:check` |
| Восстановление логов падает с `unknown_objectid_mapping` | у события нет `get_objectid_mapping()` или ключ `restore` не совпадает с тем, что регистрирует `set_mapping()` в restore-шагах | маппинг у всех событий, ключи сверяются автоматически в `moodle:check` |
| Список сдач пуст, хотя сдачи есть | `get_record('user', …, 'u.id, u.firstname…')` — префиксы в списке полей | запрашивать `'*'` или поля без префиксов |

### 16.3 Что проверено на живом Moodle 5.0.11 / PHP 8.4

`scripts/moodle-smoke.php` — 23 проверки, все зелёные: создание экземпляра и элемента журнала,
`save()` и пересдача (одна запись, один файл), содержимое файла, оценка 87.5 в `grade_grades`,
Privacy API (3 элемента), события в `logstore_standard_log`, backup → restore в новый курс
(модуль, сдача и `.lcx` переносятся), удаление экземпляра (записи и файлы).

Дополнительно пройден HTTP-путь вручную (curl + живой сервер): `view.php` (iframe, статус
«Сдано», ссылка на скачивание), `editor.php` (495 КБ, конфиг `cmid/sesskey/userid/maxbytes`
внедрён), `submit.php` (POST формы → редирект → «Макет сдан», запись в БД), `pluginfile.php`
(отдаёт `.lcx` как `application/json`, `attachment`), `submissions.php` (строка со студентом,
оценка POST → `graded`, `95.00000` в журнале).

### 16.4 Ограничения и следующий шаг

- Групповые сдачи и групповые оценки не поддерживаются (только индивидуальные).
- Нет анонимных/слепых проверок и рубрик: оценивается одна работа одним числом.
- Нет предпросмотра макета в браузере преподавателя на `submissions.php` (только скачивание
  `.lcx` и повторное открытие в редакторе) — логичный следующий шаг: рендер превью в списке.
- Moodle 4.5 не проверялся: ядро 4.5 не работает на PHP 8.4.
